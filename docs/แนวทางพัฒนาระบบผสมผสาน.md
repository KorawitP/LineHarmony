# แนวทางพัฒนาระบบผสมผสาน: Layout Engine + Linguistic Analysis

## บทนำ

เอกสารนี้สรุปแนวทางการพัฒนาระบบจัดวางข้อความภาษาไทยแบบผสมผสาน โดยรวมจุดแข็งของระบบปัจจุบัน (Layout-based) เข้ากับแนวคิดใหม่ (Grammar-based Chunking) เพื่อให้ได้ทั้งความสวยงามและความแม่นยำทางภาษา

## สถานการณ์ปัจจุบัน

### ระบบ Layout Engine ปัจจุบัน
- **วิธีการ:** Balanced Word-Wrap with Font Metrics
- **เครื่องมือ:** PyThaiNLP (newmm) + Font Metrics
- **จุดแข็ง:** 
  - ใช้ความกว้างจริงของฟอนต์
  - ผลลัพธ์สวยงามสมดุล
  - เข้าใจง่าย ใช้งานได้ทันที
- **จุดอ่อน:**
  - ไม่เข้าใจโครงสร้างภาษา
  - อาจตัดกลางวลีสำคัญ
  - ควบคุมการตัดได้จำกัด

### แนวคิด Grammar-based Chunking
- **วิธีการ:** POS Tagging + NLTK RegexpParser
- **เครื่องมือ:** PyThaiNLP (LST20) + NLTK
- **จุดแข็ง:**
  - เข้าใจโครงสร้างภาษาลึกซึ้ง
  - ควบคุมการตัดได้แม่นยำ
  - ปรับแต่งกฎได้ 100%
- **จุดอ่อน:**
  - ซับซ้อน ต้องเขียนกฎ Grammar
  - ไม่คำนึงถึงความกว้างจริง
  - ต้องการความรู้ทางภาษาศาสตร์

## แนวทางผสมผสาน: Scoring-based Hybrid Approach

### หลักการหลัก
ใช้ระบบให้คะแนนแต่ละจุดตัดบรรทัด แล้วเลือกจุดที่ได้คะแนนรวมต่ำที่สุด

```
คะแนนการตัด = Linguistic Penalty + Width Penalty + Balance Penalty + Line End Penalty
```

### กระบวนการทำงาน

#### Phase 1: Linguistic Analysis
1. **ตัดคำ** ด้วย PyThaiNLP (newmm)
2. **POS Tagging** ระบุชนิดคำ (NOUN, VERB, ADJ, etc.)
3. **Chunking** จัดกลุ่มเป็นวลี (NP, VP, PT)
4. **Confidence Assessment** ประเมินความมั่นใจของการ tag

#### Phase 2: Break Point Analysis
สำหรับแต่ละจุดตัดที่เป็นไปได้:

1. **Linguistic Penalty** - ตรวจสอบว่าตัดกลาง chunk หรือไม่
2. **Width Penalty** - ตรวจสอบว่าเกินความกว้างหรือไม่
3. **Balance Penalty** - ประเมินความสมดุลของบรรทัด
4. **Line End Penalty** - ตรวจสอบคำห้ามจบบรรทัด

#### Phase 3: Optimal Selection
เลือกจุดตัดที่ได้คะแนนรวมต่ำที่สุด

## ระบบให้คะแนน (Scoring System)

### Linguistic Penalty
กฎการตัดตามโครงสร้างภาษา:

**Level 1: ห้ามตัดเด็ดขาด (Penalty = 1000)**
- NOUN + ADJ (ดาบ|ศักดิ์สิทธิ์)
- CLAS + ADJ (เล่ม|ใหญ่)
- VERB + ADV (วิ่ง|เร็ว)

**Level 2: ตัดได้แต่ไม่ควร (Penalty = 50)**
- ADJ + CLAS (ศักดิ์สิทธิ์|เล่ม)
- ADJ + ADJ (ใหญ่|มหัศจรรย์)

**Level 3: ตัดได้สบาย (Penalty = 0)**
- ADJ + NOUN (ศักดิ์สิทธิ์|ดาบ)
- NOUN + VERB (ดาบ|ฟัน)
- NP + VP ([ดาบศักดิ์สิทธิ์]|[กำลังฟัน])

### Width Penalty
```
if line_width > max_width:
    penalty = 50 * (line_width - max_width) / max_width
```

### Balance Penalty
คำนวณจากค่าเบี่ยงเบนมาตรฐานของความกว้างแต่ละบรรทัด

### Line End Penalty
ตรวจสอบคำห้ามจบบรรทัด (และ, หรือ, เพราะ) = +20

## โหมดการทำงาน (Flexibility Modes)

### Mode 1: Strict Linguistic (เคร่งครัดทางภาษา)
- Break Inside Chunk Penalty: 1000
- Exceed Width Penalty: 10
- Max Width Tolerance: 120%
- **เหมาะสำหรับ:** เนื้อหาที่ต้องการความแม่นยำทางภาษาสูง

### Mode 2: Balanced (สมดุล - แนะนำ)
- Break Inside Chunk Penalty: 100
- Exceed Width Penalty: 50
- Max Width Tolerance: 105%
- **เหมาะสำหรับ:** งานทั่วไป บอลลูนการ์ตูน

### Mode 3: Strict Layout (เคร่งครัดรูปร่าง)
- Break Inside Chunk Penalty: 20
- Exceed Width Penalty: 200
- Max Width Tolerance: 100%
- **เหมาะสำหรับ:** งานที่ต้องการรูปร่างสวยงามเป็นหลัก

## ระบบ Confidence และ Review

### การประเมิน Confidence
ปัจจัยที่ลดความมั่นใจ:
- คำไม่อยู่ในพจนานุกรม (-0.3)
- คำที่มีตัวอักษรผสม (-0.2)
- คำยาวผิดปกติ (>10 ตัวอักษร) (-0.1)
- คำที่มีเครื่องหมายพิเศษ (-0.2)
- ชื่อเฉพาะ (-0.1)

### ระบบ Review
1. **Auto-flagging** - ระบุคำที่ confidence < 0.7
2. **Interactive Review** - ให้ผู้ใช้ตรวจสอบและแก้ไข
3. **Learning System** - จำการแก้ไขและเรียนรู้ pattern

## ตัวอย่างการทำงาน

### Input
```
"ดาบศักดิ์สิทธิ์เล่มใหญ่มหัศจรรย์กำลังฟันปีศาจ"
```

### Linguistic Analysis
```
POS Tags: [
  ("ดาบ", "NOUN"),
  ("ศักดิ์สิทธิ์", "ADJ"),
  ("เล่ม", "CLAS"),
  ("ใหญ่", "ADJ"),
  ("มหัศจรรย์", "ADJ"),
  ("กำลัง", "AUX"),
  ("ฟัน", "VERB"),
  ("ปีศาจ", "NOUN")
]

Chunks: [
  {"type": "NP", "tokens": [0,1,2,3,4], "text": "ดาบศักดิ์สิทธิ์เล่มใหญ่มหัศจรรย์"},
  {"type": "VP", "tokens": [5,6], "text": "กำลังฟัน"},
  {"type": "NP", "tokens": [7], "text": "ปีศาจ"}
]
```

### Break Point Analysis
```
จุดตัดที่ 1: ดาบศักดิ์สิทธิ์|เล่มใหญ่มหัศจรรย์...
- Linguistic: 50 (ADJ|CLAS ตัดได้แต่ไม่ควร)
- Width: 0 (ไม่เกิน)
- Balance: 15
- Line End: 0
- รวม: 65

จุดตัดที่ 4: ดาบศักดิ์สิทธิ์เล่มใหญ่มหัศจรรย์|กำลังฟัน...
- Linguistic: 0 (NP|VP ตัดได้สบาย)
- Width: 20 (เกินเล็กน้อย)
- Balance: 10
- Line End: 0
- รวม: 30 ← ดีที่สุด
```

### Output
```
ดาบศักดิ์สิทธิ์เล่มใหญ่มหัศจรรย์
กำลังฟันปีศาจ
```

## ขั้นตอนการพัฒนา

### Week 1: POS Tagging & Chunking
- สร้าง POSTagger wrapper สำหรับ PyThaiNLP
- สร้าง Chunker ด้วย NLTK RegexpParser
- ทดสอบความแม่นยำของ chunks

### Week 2: Scoring System
- เพิ่ม scoring methods
- ทดสอบกับข้อความตัวอย่าง
- ปรับค่า penalties ให้เหมาะสม

### Week 3: Integration
- ผสม linguistic analysis เข้ากับ layout engine ปัจจุบัน
- เพิ่ม config สำหรับเลือก mode
- ทดสอบกับข้อความจริง

### Week 4: Confidence & Review System
- เพิ่มระบบประเมิน confidence
- สร้าง review interface
- เพิ่ม learning system

### Week 5: Fine-tuning & Testing
- ปรับค่า penalties ตามผลลัพธ์จริง
- เพิ่ม unit tests
- เขียน documentation

## ประโยชน์ที่คาดหวัง

### ความแม่นยำ
- ลดการตัดกลางวลีสำคัญ 80%
- เพิ่มความเหมาะสมทางภาษา 60%

### ความยืดหยุ่น
- ปรับโหมดได้ตามงาน
- เรียนรู้จากการใช้งาน
- ควบคุมได้ละเอียด

### ประสิทธิภาพ
- รักษาความเร็วเดิม
- เพิ่มคุณภาพผลลัพธ์
- ลดการแก้ไขด้วยมือ

## ข้อควรระวัง

### ความซับซ้อน
- ระบบซับซ้อนขึ้น ต้องการการทดสอบมากขึ้น
- ต้องการ fine-tuning penalties อย่างระมัดระวัง

### ประสิทธิภาพ
- POS tagging ใช้เวลามากกว่าการตัดคำธรรมดา
- ต้องการ caching สำหรับข้อความที่ซ้ำ

### ความแม่นยำของ POS
- PyThaiNLP อาจ tag ผิดกับคำใหม่/คำเฉพาะ
- ต้องมีระบบ fallback และ review
